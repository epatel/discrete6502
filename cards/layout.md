# layout

Board layout v6 (die-mimicry final form, user-approved 2026-07-19), the pipeline, its geometry rules, and routing status.

**Board concept**: 283 × 309.6 mm (die aspect 0.92, "30cm class" per user), reads as the 6502 die itself. Front face = ONLY transistors (SOT-323) + inline register LEDs, each at its die-scaled coordinate on a 3.0 × 2.2 mm collision grid at ~36% occupancy — the die's own density variations (PLA stripes, sparse random logic, real gaps) reproduce themselves; median placement displacement 1.5 mm. Bond pad ring: 4×4→**11.6 mm square THT pads** (die-true size, measured ~390 die units from segdefs) with 2.5 mm croc-clip holes, at die-true bond pad positions, silk-labeled. Back face: all passives (pull-ups at node centroids, protection/bulk/decouplers in the rim band beside their pads) + unpopulated **Pico 2 W site** (SMD/castellated variant, `Module:RaspberryPi_Pico_W_SMD`) behind the die's natural gap; only its antenna strip (42×18) is an all-layer keepout. 26 DNP series resistors below the module wire DB0-7/AB0-13/CLK0/RES/RW/SYNC to its GPIOs.

**Pipeline** (strict order, regenerate from scratch each time):
1. `tools/gen_netlist.py` (plain python3) — netlist + die/bond-pad positions. FET = 2N7002W SOT-323 (LCSC **C82175-verify** — confirm exact part at order time).
2. `tools/gen_pcb.py` (KiCad bundled python) — placement, board outline, min-via rules (0.4/0.15 in the generated `.kicad_pro` — stitch vias are 0.45/0.2).
3. `tools/route_power.py` — planes (GND=In1, VCC=In2) + ~3,700 stitch vias. Two-tier placer: **phase 1** claims a deterministic in-cell via spot per core power pad — SPOT_F=(+1.05,+0.75) for front pads, SPOT_B=(+1.05,−0.75) for back pads, legal by grid construction (LED cells excluded; opposite-face copper checked only inside the Pico envelope); **phase 2** spiral-searches occupancy bitmaps (static pads + dynamic vias/tracks, 0.25 mm raster, 0.45 inflation, 0.12 mm segment sampling) for periphery/leftovers. Then `tools/route_power_finish.py` **run against the presignal snapshot** stitches every remaining vss/vcc pad (exact-geometry via spots, L-shaped escapes, same-net-attach fallback) — MUST happen before signal routing: run after, ~14 pads are unfixable because signal tracks consume the room (learned the hard way). Snapshot ends with power 100% done; the signal router sees the stitch vias as obstacles.
4. `tools/route_nc.py` — negotiated-congestion signal router (PathFinder-style). History: Freerouting 700/8,500 in 10h; greedy Python router (`tools/route_signals.py`, kept for reference) saturated at 46–53% by congestion collapse. route_nc.py restores `gen/board_presignal.kicad_pcb` itself, extracts the obstacle grid + pads, runs the C core (`tools/route_nc.c`, auto-compiled to `gen/route_nc`): nets route THROUGH conflicts paying use×pres + history penalties; each iteration rips & reroutes only conflicted nets; env knobs ROUTE_NC_{MAXIT,MAXSEC,PRESMAX,HINC,VIACOST} (good: 3000/2000/40/80 — soft pres cap + strong history beats a huge pres cap, which oscillates); ~1 s/iteration. Rules: **0.127/0.127 (5 mil, JLC 4-layer capable) on G=0.26mm** (adjacent cells = 0.133 gap, legal; INFLATE 0.2); route_nc.py also syncs netclass/min_clearance in the `.kicad_pro`. F.Cu horiz / B.Cu vert, via 0.45/0.2 = 3×3 usage stamp both layers + static ring check, per-net cell dedup so junctions/same-net crossings never self-conflict, failed pads never seed the tree (the poisoning lesson), whole-net carve during tree build (a pad's own inflation ring must not moat it off when it's the join TARGET), stubs + junction anchor-bridges to pad centers on emission. Extraction traps (each cost a debug session): (a) **paste/mask-only pads have no copper** — skip pads on neither F.Cu nor B.Cu, else the Pico's 3.8×2.2 B.Paste anchors become phantom obstacles that seal its pins; (b) **diagonal tracks must be rasterized along their length** — bbox-marking a long diagonal blocks a huge rectangle (sealed pull-up pads, wasted whole corridors); (c) keepout rule-areas live inside `fp.Zones()` (the Pico's RF/antenna zones), not `board.Zones()`, and the layout_params antenna rect is oversized — read the real zones. Trust ONLY `tools/check_gaps.py` (independent union-find connectivity → `gen/gaps.json`) for completion claims.
5. Finishing passes (both required for DRC-clean): `tools/fix_same_net_vias.py` (merge same-net vias < 0.45mm — hole-to-hole; delete vias on same-net PTH pads; stub only layers with copper at the removed spot) then `tools/fix_via_pairs.py` (nudge different-net via pairs < 0.577mm to exact-geometry-legal spots, dragging track endpoints). Board is **6-layer** since 2026-07-24: In1=GND, In4=VCC planes; F/In2/In3/B route H/V/H/V; snapshot converted by one-off surgery (SetCopperLayerCount + VCC zone→In4). Emission correctness rules (hard-won): goal cells strictly inside pad copper (stubs never leave own pad); carve filtered against a non-pad hard mask (never release via/track/keepout cells).
6. `tools/dump_layout.py` → `gen/layout.json` for the HTML previewer (`tools/preview_server.py`, port 8623, comments → `gen/preview_comments.jsonl`; draws true fab-outline+pad body sizes — bbox drawing misled the user once).

Hard-won rules (don't regress): back parts sit AT cell centers (the via-spot math depends on it); pin-header/Pico footprint origins are not body centers — measure before reserving; the SMD Pico's only real keepout is the antenna strip; KiCad stock courtyards are ~30% oversized vs JLC reality (severities ignored in `.kicad_pro`, pad-clearance DRC is the electrical check); 2 permanent DRC items are internal to the Pico library footprint (its own paste pads vs its own keepout — benign, DNP).

Iteration protocol with the user: HTML preview at localhost:8623 + comment box (Monitor watches the jsonl); judge the *KiCad render*, not the preview, for anything visual — the preview is boxes.

Remaining for M5: import `.ses`, DRC, board-vs-netlist parity, renders, then JLC fab outputs (gerbers/BOM/CPL; BOM: verify 2N7002W LCSC + note PCB ≈ 8.8 dm² → fab ~$300–400/5). Open: clk0 pull-up/down when nothing drives it; via-free zone under Pico if user wants it.
