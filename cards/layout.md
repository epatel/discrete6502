# layout

Board layout v6 (die-mimicry final form, user-approved 2026-07-19), the pipeline, its geometry rules, and routing status.

**Status: M5 complete** — board fully routed on 6 layers, 0 electrical DRC violations, 0 unconnected;
golden copy `gen/board_routed_golden.kicad_pcb`, fab package in `gen/fab/`.

**Board concept**: 290.7 × 322.0 mm final outline (die aspect, "30cm class" per user), reads as the 6502 die itself. Front face = ONLY transistors (SOT-323) + inline register LEDs, each at its die-scaled coordinate on a 3.0 × 2.2 mm collision grid at ~36% occupancy — the die's own density variations (PLA stripes, sparse random logic, real gaps) reproduce themselves; median placement displacement 1.5 mm. Bond pad ring: 4×4→**11.6 mm square THT pads** (die-true size, measured ~390 die units from segdefs) with 2.5 mm croc-clip holes, at die-true bond pad positions, silk-labeled. Back face: all passives (pull-ups at node centroids, protection/bulk/decouplers in the rim band beside their pads) + unpopulated **Pico 2 W site** (SMD/castellated variant, `Module:RaspberryPi_Pico_W_SMD`) behind the die's natural gap; only its antenna strip (42×18) is an all-layer keepout. 26 series resistors (1k, factory-populated) below the module wire DB0-7/AB0-13/CLK0/RES/RW/SYNC to its GPIOs.

**Pipeline** (strict order, regenerate from scratch each time):
1. `tools/gen_netlist.py` (plain python3) — netlist + die/bond-pad positions. FET = **BSS138K SOT-323, LCSC C504052** (switched from 2N7002W/C139444 at order time 2026-07-25 — not in JLC inventory; BSS138 was the M2-designated, SPICE-validated fallback). The 26 Pico GPIO series resistors (1k, C11702) are **populated** in factory assembly, not DNP.
2. `tools/gen_pcb.py` (KiCad bundled python) — placement, board outline, min-via rules (0.4/0.15 in the generated `.kicad_pro` — stitch vias are 0.45/0.2).
3. `tools/route_power.py` — planes (GND=In1, VCC=In2 **as written — the 6-layer surgery in step 5 moves VCC to In4**; a from-scratch rerun must repeat that surgery or the script must be updated) + ~3,700 stitch vias. Two-tier placer: **phase 1** claims a deterministic in-cell via spot per core power pad — SPOT_F=(+1.05,+0.75) for front pads, SPOT_B=(+1.05,−0.75) for back pads, legal by grid construction (LED cells excluded; opposite-face copper checked only inside the Pico envelope); **phase 2** spiral-searches occupancy bitmaps (static pads + dynamic vias/tracks, 0.25 mm raster, 0.45 inflation, 0.12 mm segment sampling) for periphery/leftovers. Then `tools/route_power_finish.py` **run against the presignal snapshot** stitches every remaining vss/vcc pad (exact-geometry via spots, L-shaped escapes, same-net-attach fallback) — MUST happen before signal routing: run after, ~14 pads are unfixable because signal tracks consume the room (learned the hard way). Snapshot ends with power 100% done; the signal router sees the stitch vias as obstacles.
4. `tools/route_nc.py` — negotiated-congestion signal router (PathFinder-style). History: Freerouting 700/8,500 in 10h; greedy Python router (`tools/route_signals.py`, kept for reference) saturated at 46–53% by congestion collapse. route_nc.py restores `gen/board_presignal.kicad_pcb` itself, extracts the obstacle grid + pads, runs the C core (`tools/route_nc.c`, auto-compiled to `gen/route_nc`): nets route THROUGH conflicts paying use×pres + history penalties; each iteration rips & reroutes only conflicted nets; env knobs ROUTE_NC_{G,MAXIT,MAXSEC,PRESMAX,HINC,VIACOST,SCALE,HIST_IN,HIST_OUT} (good: PRESMAX=2000, HINC=40, VIACOST=80 — soft pres cap + strong history beats a huge pres cap, which oscillates; hist checkpointed every 200 iters so a run is warm-startable); ~1 s/iteration. Rules: **0.127/0.127 (5 mil) on G=0.13mm** — the coarse G=0.26 grid plateaued at ~50 conflicted nets (quantization knots, not capacity); the fine grid with SCALE=2 body/halo stamping in the C core broke through to zero. **4 routing layers** since the 6-layer switch: F/In2/In3/B alternate H/V/H/V. route_nc.py also syncs netclass/min_clearance in the `.kicad_pro`. Via 0.45/0.2 = 3×3 usage stamp both layers + static ring check, per-net cell dedup so junctions/same-net crossings never self-conflict, failed pads never seed the tree (the poisoning lesson), whole-net carve during tree build (a pad's own inflation ring must not moat it off when it's the join TARGET), stubs + junction anchor-bridges to pad centers on emission. Extraction traps (each cost a debug session): (a) **paste/mask-only pads have no copper** — skip pads on neither F.Cu nor B.Cu, else the Pico's 3.8×2.2 B.Paste anchors become phantom obstacles that seal its pins; (b) **diagonal tracks must be rasterized along their length** — bbox-marking a long diagonal blocks a huge rectangle (sealed pull-up pads, wasted whole corridors); (c) keepout rule-areas live inside `fp.Zones()` (the Pico's RF/antenna zones), not `board.Zones()`, and the layout_params antenna rect is oversized — read the real zones. Trust ONLY `tools/check_gaps.py` (independent union-find connectivity → `gen/gaps.json`) for completion claims.
5. Finishing passes (all required for DRC-clean): `tools/fix_same_net_vias.py` (merge same-net vias < 0.45mm — hole-to-hole; delete vias on same-net PTH pads; stub only layers with copper at the removed spot) then `tools/fix_via_pairs.py` (nudge different-net via pairs < 0.577mm to exact-geometry-legal spots, dragging track endpoints), then `tools/enlarge_vias.py` (grow vias to 0.55mm pad / 0.30mm drill so the FREE JLC 0.3mm drill class can be used without losing annular ring; size ladder 0.55/0.52/0.45, nudge only when shrinking will not do). **Three traps it cost to learn:** (a) a segment indexed only at its endpoints is invisible to a via beside its middle — sample along the length (first run: 45 clearance errors + 5 shorts); (b) a via sitting inside a same-net pad IS that pad's connection to the plane — never move it, only resize (first run broke a vss pad); (c) `min_via_annular_width` defaults to 0.1mm, so 0.45mm pads are illegal at a 0.3mm drill — the pass relaxes the rule to 0.075 to match JLC's actual capability. Board is **6-layer** since 2026-07-24: In1=GND, In4=VCC planes; F/In2/In3/B route H/V/H/V; snapshot converted by one-off surgery (SetCopperLayerCount + VCC zone→In4). Emission correctness rules (hard-won): goal cells strictly inside pad copper (stubs never leave own pad); carve filtered against a non-pad hard mask (never release via/track/keepout cells).
6. `tools/dump_layout.py` → `gen/layout.json` for the HTML previewer (`tools/preview_server.py`, port 8623, comments → `gen/preview_comments.jsonl`; draws true fab-outline+pad body sizes — bbox drawing misled the user once).

Hard-won rules (don't regress): back parts sit AT cell centers (the via-spot math depends on it); pin-header/Pico footprint origins are not body centers — measure before reserving; the SMD Pico's only real keepout is the antenna strip; KiCad stock courtyards are ~30% oversized vs JLC reality (severities ignored in `.kicad_pro`, pad-clearance DRC is the electrical check); 2 permanent DRC items are internal to the Pico library footprint (its own paste pads vs its own keepout — benign, DNP).

Iteration protocol with the user: HTML preview at localhost:8623 + comment box (Monitor watches the jsonl); judge the *KiCad render*, not the preview, for anything visual — the preview is boxes.

**Silkscreen** (`tools/add_silk.py`, last pipeline step before fab): classic 6502 pin names + DIP-40 numbers placed *beside* each bond pad (never on it — user directive; real ink clears pad copper by 0.54 mm, though KiCad's padded text bboxes make it look like an overlap). Region bands + register letters (whitelist A,X,Y,S,P,PCL,PCH — origins like nmi/irq/clk0 are protection diodes) + the "MOS 6502 / discrete6502 / after visual6502.org · CC BY-NC-SA" plate. Library-drawn silk frames *on* pads are stripped (144) in a `--frames-only` subprocess — a destructive pass and a reload must never share a KiCad python process.

**Silk must not cross pads** (learned from the first gerber review, 2026-07-26): the fab subtracts pad openings from silk, so text over the FET field prints half-eaten ("CONTROL LOGIC" came out as "COITROL LOGIC"). `add_silk.py` now builds a 2 mm occupancy grid of front footprints and places every free-standing text in a pad-free block: the logo picks first (largest block it fits, attribution split over two lines — one long line needs more clear width than exists anywhere on the die), then band titles at ONE uniform height that all three bands can honour, each taking the longest wording that fits ("INSTRUCTION DECODE (PLA)" → "DECODE PLA", "DATAPATH — REGISTERS & ALU" → "DATAPATH"), then register letters near their LED rows. The die is dense enough that a full-length title at 2.6 mm (~64 mm wide) never fits — the largest pad-free block in any band is ~36 × 14 mm.

**Fab outputs** (`gen/fab/`): gerbers zip (13 layers + drill), `discrete6502_bom.csv` (9 parts, 5,328 placements; Designator cells chunked to ≤2000 chars — JLC rejects >2048), `discrete6502_cpl.csv` (4,106 top / 1,222 bottom), `README.md` order settings, `ordering.html` interactive checklist. PCB ≈ 9.4 dm²; real cart quote 2026-07-25: €131 PCB (5 pcs, ENIG) + €716 PCBA (both sides).

Open items for bring-up (not board changes): clk0 has no pull-up on the board, so it must be driven **push-pull** — an open-drain clock would leave it floating unless an external 10k is croc-clipped Φ0→VCC. A 3.3 V clock into a 5 V core is fine (clk0 gates only two pull-downs; the internal phases are regenerated at full rail) — see `pico-controller/README.md`.
